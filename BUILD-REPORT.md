## What was built

**NEONHARBOR** — an original top-down 2D open-world crime game (GTA 1/2
style). Vanilla ES modules on one `<canvas>`; all art and sound generated in
code; zero libraries, zero assets, zero network requests.

- A drivable city grid (2560×1792, 6 avenues, 5 streets, marina + beach):
  walk, drive, enter/exit cars (E), acceleration/brake/steering/handbrake.
- Traffic AI cars (lanes, intersections, car-ahead braking) and pedestrians
  on sidewalks who flee danger; parked cars in lots to steal; NPC cars to
  jack (driver flees on foot).
- Wanted 1–5 stars: foot cops chase and arrest (~1.2 s standing on you =
  BUSTED, $100 bail), police cars chase and ram; heat decays when unseen,
  cleared at the safehouse.
- 6 story missions with dialogue banners and payouts ($150–$1,200) plus
  repeatable taxi fares: First Fare, Hot Wheels (steal the yellow Sunray),
  The Tail (follow 45 s, don't get spotted), Getaway (lose 3 stars), The
  Drop (60 s, starts at 2 stars), Harbor Heist (hold the vault 6 s past
  armed guards, lose the heat, reach the Loft).
- Combat: fists/melee + pistol (ammo, $40/12 rounds), health pickups via
  Med Stop, armed bank guards who shoot back.
- Money, car repair ($80), safehouse save in localStorage + continue.
- HUD: wanted stars, cash, health bar, ammo, objective line, context prompt
  (Q), controls hint; minimap (player, cars, mission marker, cops).
- Polish: particles, screen shake, skid marks, WebAudio synth SFX (engine,
  sirens, shots, pickups) + generative music, dusk lighting/vignette,
  pause, title/how-to/game-over/busted/victory screens, restart.
- Hidden `?debug=1` helpers (`window.__NEONHARBOR__`: setWanted, setMission,
  teleport, giveCash, addHeat) and `?shot=…` staging — test-only, out of
  the normal flow.

## Bugs found and fixed during testing

1. **Mission 3 (follow) completed instantly.** The step's `time` field was
   used both as a countdown and as the in-band progress counter, so the
   first in-band tick hit the target. Fixed: the follow step now uses a
   separate `duration` + `followProgress` field (`config.js`,
   `missions.js`).
2. **Traffic cars rammed each other in opposite lanes.** Circle collision
   (radius ≈ length/2) treated two cars passing 44 px apart as a crash.
   Fixed: oriented overlap in each car's own frame (`vehicles.js`
   `collideCars`); opposite-lane passing is now clean, rear-ends and
   T-bones still collide. Lane widened 22 → 26 px; the car-ahead check
   narrowed to the same lane (side < 28).
3. **Roadside parked cars blocked a driving lane.** The 96 px roads fit
   two driving lanes; a curb-parked car intruded into the near lane.
   Fixed: roadside parking removed; lots hold the parked cars (`city.js`).
4. **Landmark names drew twice.** Building labels + zone-marker labels
   both named the bar/bank/loft. Fixed: landmark buildings carry no text
   label; the zone marker names them (`render.js`).
5. **Taxi fares offered during a police chase.** Fixed: no fare offers
   while wanted (`missions.js`).
6. **Start banner overlapped the HUD objective in screenshots.** Fixed:
   reset banner shortened 4 s → 2 s (`world.js`).
7. **Test-harness fixes (not game bugs):** the bundle builder's
   `String.replace` expanded `$'` sequences from the game source
   (corrupted one line); fixed with a function replacement
   (`tests/bundle.mjs`). Duplicate top-level names across modules
   (`nearestLine`, `angleDiff`, `ctx`, `COLORS`, `muted`) broke the
   single-file bundle; renamed per file (`pedestrians.js`, `police.js`,
   `audio.js`, `main.js`). This VM's browser blocks `http://127.0.0.1`
   navigations from CDP (same LNA block as best-game), so the harnesses
   run the game from `tests/bundle.html` via `file://` (same code,
   import/export stripped); the device-metrics override is set before
   navigation so the game never sees a resize; the test browser runs on
   port 9227 (the best-game browser on 9226 died in a VM restart).

No new bugs were found in the re-seal session: every re-run test passed
on the first attempt, and no game file needed a real fix — the re-write
was byte-identical (sha256 unchanged for all 34 files).

## Known issues / tuning notes

- **FPS in headless Chrome is load-dependent.** The playtest measured
  35 fps in this VM's software-rendered (SwiftShader) headless Chrome.
  The game loop is dt-based (dt clamped at 0.05 s), so play stays
  correct at any fps ≥ 20 — every timed check (2 s drive, 45 s tail,
  mission timers) passed at those rates. Desktop Chrome with GPU canvas
  should run it at 60. Render was optimised: view culling for
  roads/buildings, precomputed building windows, cached vignette.
- **Difficulty:** police rams damage the player (6 HP/s in contact) and
  the heist guards shoot back; a careless driver can be busted or wasted
  in the first minutes. The Loft (free heat clear + save) is a short drive
  from the bar. If the parent wants it softer, the cheapest knobs are
  `WANTED.decayPerSec` / `COMBAT.guardDamage` in `config.js`.
- The vignette makes the world edges dark (dusk mood); the minimap is
  small but readable.
- `?debug=1` writes a best-score entry only when the run ends; real games
  record it correctly.
